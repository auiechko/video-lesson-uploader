# Lesson Video Uploader

Python/Telethon-застосунок, у якому одна одиниця надсилання — це один календарний
урок, а не один відеофайл. Усі MP4 одного `calendar_event_id` надсилаються одним
Telegram media group у заданому хронологічному порядку.

## Windows GUI — рекомендований спосіб

Після встановлення запустіть [start-gui.cmd](start-gui.cmd) подвійним кліком.
Командний рядок для щоденної роботи більше не потрібний.

У вкладці **Telegram і безпека**:

1. Введіть `API ID`, `API hash`, номер телефону та натисніть
   **Зберегти налаштування**.
2. `API hash` потрапляє у Windows Credential Manager, а не у `config.toml`.
3. Натисніть **Увійти в Telegram** і введіть код та, за потреби, пароль 2FA
   у діалогових вікнах.

У вкладці **Уроки та надсилання** можна:

- указати чат (`me`, `@username` або числовий ID приватної групи —
  див. [Як дізнатися ID чату](#як-дізнатися-id-чату));
- додати один чи кілька уроків;
- вибрати MP4 через Провідник і змінити їх порядок кнопками;
- побачити один логічний preview-рядок на урок;
- повернути вибраний урок у редактор кнопкою **Редагувати вибраний урок**
  (працює і для пакета, відкритого з JSON);
- відкрити або зберегти локальний batch JSON;
- надіслати пакет або перевірити невідому доставку.

У вкладці **Google Calendar**:

1. Виберіть OAuth-файл `credentials.json` типу **Desktop app**.
2. Натисніть **Підключити Google** і підтвердьте доступ у браузері.
3. Виберіть календар, діапазон дат і натисніть **Завантажити події**.
4. Двічі клацніть подію або натисніть **Імпортувати вибрану подію в урок**.
5. Перевірте розпізнані поля, додайте MP4 та сформуйте пакет.

Застосунок запитує лише доступ до календаря для читання. OAuth token
зберігається у Windows Credential Manager, а не у файлі `token.json`.
Кнопка **Відключити** видаляє цей token. Події на весь день, скасовані події та
події з некоректною тривалістю пропускаються. Точний Google `event_id`
зберігається як `calendar_event_id`, тому відео різних уроків не змішуються.

Підтримуються, зокрема, такі назви з робочого календаря:

- `105813989 Сервер Османов (Ільяс 10) Учечко ТГ`;
- `106248208 Valentyna Stoieva ТГ (Поліна 15р) JAVA | Учечко`.

У першому випадку редактор отримає `105813989`, `Ільяс`, `10р індив`; у
другому — `106248208`, `Поліна`, `15р JAVA`. Це лише початкове заповнення:
усі поля можна відредагувати перед додаванням уроку.

Файли `batch*.json` і `config.toml` виключені з Git, оскільки можуть містити
приватні дані учнів. Приклад маніфесту залишається у репозиторії.

## Поведінка

- 1 MP4 — звичайне media message з одним caption.
- 2–10 MP4 — один Telegram-альбом і один спільний caption без суфіксів
  `(частина 1/…)`.
- 11+ MP4 — послідовні групи по 10; caption отримує лише суфікс
  `(альбом 1/2)`, `(альбом 2/2)` тощо.
- Дво- й тригодинні та пробні уроки мають суфікси `ДВІ ГОДИНИ`,
  `ТРИ ГОДИНИ`, `(пробне)`.
- SQLite зберігає впорядковані шляхи, статус, усі Telegram message IDs і
  `grouped_id` кожної фізичної media group.
- `SENT`, `DELIVERY_UNKNOWN` та `PARTIALLY_CONFIRMED` захищають урок від
  небезпечного автоматичного повторного надсилання.

## Встановлення

Потрібен Python 3.11 або новіший.

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
Copy-Item config.example.toml config.toml
```

Активація venv не потрібна. Якщо PowerShell блокує `Activate.ps1`, це не заважає
ані встановленню, ані запуску GUI.

### Одноразове налаштування Google Calendar

1. У Google Cloud створіть або виберіть проєкт і ввімкніть **Google Calendar
   API**.
2. Налаштуйте OAuth consent screen.
3. Створіть OAuth Client ID з типом **Desktop app** і завантажте JSON.
4. Запустіть GUI та виберіть цей файл у вкладці **Google Calendar**.

Офіційна інструкція:
[Google Calendar API Python quickstart](https://developers.google.com/workspace/calendar/api/quickstart/python).
Локальний redirect у браузері використовується тільки під час входу настільного
застосунку.

CLI залишається доступним для автоматизації.

## Де зберігається `api_hash`

`api_id` і номер телефону лежать у `config.toml`. `api_hash` — ні; він
шукається у двох місцях, у такому порядку:

1. Змінна середовища, названа в `telegram.api_hash_env` (типово
   `TELEGRAM_API_HASH`).
2. Windows Credential Manager — туди його записує GUI.

Обидва входи, GUI і CLI, користуються цим самим правилом, тож збережений у
застосунку hash доступний і для CLI. Змінна середовища перекриває сховище,
якщо треба разово підставити інший ключ:

```powershell
$env:TELEGRAM_API_HASH = "ваш_api_hash"
```

`config.toml`, `.env`, Telethon session і локальна SQLite-БД виключені з Git.

## Як дізнатися ID чату

Поле `target_peer` у маніфесті (у GUI — «Telegram-чат») приймає три формати:

| Значення | Куди піде |
| --- | --- |
| `me` | Обране (Saved Messages) — зручно для перевірки |
| `@username` | Публічний канал або група з юзернеймом |
| `-1001234567890` | Приватна група чи канал за числовим ID |

Найпростіше подивитися ID чатів, до яких акаунт уже має доступ:

```powershell
lesson-video-uploader chats --config config.toml
```

Команда нічого не надсилає — лише виводить `ID` і назву кожного діалогу, звідки
значення можна скопіювати. Потрібен уже виконаний вхід у Telegram.

Якщо шукати вручну: перешліть будь-яке повідомлення з потрібного чату боту на
кшталт `@JsonDumpBot`, або увімкніть у Telegram Desktop експериментальну опцію
показу Peer ID у профілі. ID супергруп і каналів починається з `-100`.

## Маніфест уроків

Скопіюйте [manifest.example.json](manifest.example.json) і замініть дані.
Кожен елемент `lessons` відповідає рівно одному Calendar event. `videos` можна
записувати коротко як список шляхів або як об’єкти з явним `order`; два відео
одного уроку не можуть мати однаковий `order`. Відносні шляхи рахуються від
папки маніфесту. Перед preview перевіряється, що кожен файл існує та має
розширення `.mp4`.

Поля `student_id`, `student_name`, `lesson_label`, `duration_hours` та
`is_trial` — це те, з чого збирається caption. Замість них можна задати готовий
`caption` напряму; саме так виглядає пакет, збережений із GUI. Якщо вказати і
`caption`, і ці поля, до Telegram піде `caption`, а поля збережуться, щоб пакет
можна було відкрити назад у редакторі.

Подивитися один логічний рядок на урок:

```powershell
lesson-video-uploader preview batch.json
```

Розгорнути впорядковані файли:

```powershell
lesson-video-uploader preview batch.json --expand
```

Надіслати:

```powershell
lesson-video-uploader send batch.json --config config.toml
```

При першому запуску Telethon попросить увійти в Telegram. Якщо урок має понад
10 відео, перед надсиланням буде показане попередження. Відсоток прогресу
рахується за всіма відео уроку разом, а не окремо для кожного файлу.

Якщо з’єднання обірвалося після початку upload або Telegram повернув не всі
message IDs, стан стає `DELIVERY_UNKNOWN` чи `PARTIALLY_CONFIRMED`. Наступний
запуск не надсилає урок повторно. Спочатку запустіть read-only перевірку:

```powershell
lesson-video-uploader reconcile batch.json --config config.toml
```

Команда читає останні повідомлення групи й порівнює caption, упорядковані назви,
розміри файлів та приблизний час. Лише один однозначний повний збіг стає `SENT`.
Неповний збіг стає `PARTIALLY_CONFIRMED`; дублікати чи неоднозначні результати
лишаються `DELIVERY_UNKNOWN` і потребують ручної перевірки.

## Тести

Тести не звертаються до Telegram і використовують mock-клієнт:

```powershell
python -m unittest discover -v
```

Покриті одиночні відео, альбоми з 2, 3 і 10 MP4, межа 11 MP4, captions,
ізоляція Calendar events, збереження всіх message IDs, часткова/невідома
доставка, безпечне reconciliation, ідемпотентний повторний запуск, preview,
наскрізний прогрес, round-trip маніфесту, пошук `api_hash` та конфігурація.

CI ганяє цей самий набір на Windows і Linux для Python 3.11–3.13. Linux там
потрібен як запобіжник: Windows-специфічні імпорти не повинні потрапляти у
спільні модулі.
